# 助理系统架构

> 状态：已部署（表述待按 CachyOS 更新） · 角色：常驻服务与凭证的运行面约定

## 组成

- **事件层**：`eventd`（入账、判定、调度、计龄）与 `ev` CLI。这是唯一能写账的进程，见[事件规格 §2](event-spec.md)。
- 交互层：DS-Bot Web/Desktop（见 [DS-Bot 入口层选型](ds-bot-entry.md)）与各 CLI / 桌面 agent，统一规则入口（见[多 agent 协作](agent-collaboration.md)）。
- 常驻层：需要持续在线的服务用用户级 systemd 单元管理，开机自启、静默运行。
- 命令入口层：`~/.local/bin/` 的薄包装脚本，只做环境修正与转发，不承载逻辑。
- 记录层：每次维护/部署留下任务记录，完成后归档，配置源与历史分离。

## 常驻服务

按依赖顺序启动；除 `eventd` 外任一停摆都不影响其它层工作，账仍然可读。

| 服务 | 职责 | 停摆后果 | 恢复方式 |
|---|---|---|---|
| `event.socket` | 本机 CLI 提交入口 | `ev` 不可用，源侧 spool 继续堆积 | socket activate |
| `eventd` | 入账、判定、派发、计龄 | 不再有新事件落定；**spool 不丢** | 重启后重扫 spool |
| `renderd` | 呈现面出图（[渲染管线](render-pipeline.md)） | 屏停在上一次刷新 | 重启即补渲 |
| `ev-watch.service` | 外部检查点：查进展与偏离（[架构总览 §10.2](architecture.md)） | 卡住的任务无人发现 | 独立 timer，不依赖 eventd 内部逻辑 |

**`ev-watch` 必须在 `eventd` 之外**。同一进程里做自检，等于让失控的单元判断自己是否失控。

## 凭证与状态

- 凭证保留在各应用原生位置，不进仓库、不进配置源、不进规则文件。
- 服务令牌、会话数据库按"仍被使用"处理，不按缓存清理。
- **处理器拿到的是句柄，不是凭据**。执行方需要凭据时向本地 broker 换一次性句柄（可设 TTL 与作用域），broker 在首次使用时才取用真实值；处理器环境变量里不得出现 token（[事件规格 §5.1](event-spec.md)、[§12.3](architecture.md)）。这一条针对的是最现实的泄露路径：模型读到上下文，再原样写进日志或提交。
- 账里不存凭据。payload 出现疑似密钥即脱敏并记 `system.secret_detected`。

## 自动化边界

沿用[架构总览 §5](architecture.md) 的分类，不另立：

- **`read`**：可自动，事后记账。
- **`revertible`**：先通知再执行，必须附回退路径。
- **`irreversible`**：一律要人确认；发布、推送、删除、转账、发消息都在这类。定时任务与开机自启**只承载前两类**。
- 事件来源的信任等级（`trusted` / `untrusted`，两档）在派发前查一次，决定它能不能自动执行；规则只能降级、不能升级（[事件规格 §3](event-spec.md)）。

## 监督方的边界

外部检查点可以做的事与此不可以做的事，必须写死：

| 允许 | 禁止 |
|---|---|
| 标记 `escalated` 并附检查点差异 | 直接改规则包 |
| 重启卡死的处理进程（有回退路径时） | 代处置方落定事件 |
| 生成"规则候选"工单 | 自己执行不可逆动作 |
| 通知人并给出一句话结论 | 在账里写非事实内容 |

第一列都可以回退；第二列都会让系统无法自证。检查点本身出错时，行为是"什么都不做并报警"，不是"尽力而为"。
