# 墨水屏显示模块产品线(看板/标签系列)

定位:助手系统的**物理输出面**——agents 推内容,模块只管渲染显示;
模块是无状态显示终端,内容管线统一在服务端。KPW5 固件逆向(`~/Repos/kpw5-analysis`)
当**范例**:其波形/时序/电源/锁闭生态的分析结论,转成本产品线的选型原则
(见 §3)。价格均为估价,下单前重新核价。

## 选型四标准(硬门槛)

1. **固件开源良好**:驱动库/固件可改可自部署,不依赖厂商云
2. **做工**:正面全白/窄边框优先,能直接放桌面/上墙不丑
3. **高性价比**:同尺寸下选成熟件,不买裸屏自研(那是另一条工程线)
4. **生态**:有 Arduino/MicroPython/Home Assistant 现成对接

## 2. 统一渲染架构(模块是哑终端)

```
内容源(agents/cron/HA/MQTT 事件)
  → 模板渲染(HTML/SVG → 服务端光栅化 → 1bpp/8bpp PNG)
  → 推送层:
      WiFi 系(Inkplate/M5/TRMNL): 模块定时拉 HTTP / MQTT 推
      ESL 系: OpenEPaperLink AP → BLE 广播(tag 端休眠唤醒收图)
  → 模块刷帧(各家 lib,统一只认 PNG+刷新模式标志)
```

- **服务端统一出图**:任何模块来要内容,拿到的都是同一张位图+meta
  (partial|full);屏蔽各家刷帧 API 差异(KPW5 96B ioctl 差异的教训:
  出口抽象一次,下游随便换)
- **内容类型**:agent 状态卡/日历/待办/系统监控/通知队列/环境数据
- **离线兜底**:模块无网时显示最后帧+时间戳(墨水瓶天性,不丢人)

## 3. KPW5 范例 → 产品原则

| 固件分析结论 | 转成产品线的规矩 |
|---|---|
| 波形按温度分 13 bank 切换 | 模块固件必须支持温度自适应波形(epdiy/Inkplate/OEPL 已内置——裸屏自研才要操这心) |
| 局部刷新+Regal 反鬼影机制 | 内容设计:小区域更新用 partial;每 N 次 partial 插一次全刷;避免大面积黑白反转 |
| VCOM 逐台校准+fiti PMIC 时序 | **买成品板不碰裸屏**——电源/校准人家调好了,这正是选成品的核心收益 |
| 16 灰 LUT(实际 4bpp) | 出图管线做 4 灰抖动而非 256 灰截断 |
| 波形帧周期 ~10ms | ESL/慢刷新模块是数秒级——别期待动画,设计"翻页式"信息 |
| Amazon 锁闭生态(tmd/签名/verity) | 一切买开源固件硬件;KPW5 本体永远只是"范例+屏供应商" |

## 4. 推荐采购与最小闭环

**首发组合(~¥600-900,覆盖两档)**:
- AP 网关 + **2.9" ESL 标签 ×3**(¥200-300 全套)→ 跑通 BLE 标签生态
- **Inkplate 5**(¥450-650)→ 桌面助手卡主力

**最小闭环**(首个里程碑):
`agent 定时任务 → 渲染 PNG → ESL 显示"机房状态" + Inkplate 显示"今日日程"`
—— 跑通后再上 Tier 3 墙板。

**后续扩展**:TRMNL 或 Inkplate 10 上墙;ESL 11.6" 做门口/会议室标牌;
KPW5 屏若拆下来(路线 A)直接变 Tier 3 自研件(epdiy 路径已验证)。

## 5. 未决项

- Inkplate 无壳 → 相框/3D 打印白框方案,做工分怎么补
- ESL 刷新延迟(BLE 广播间隔)对"实时性"需求的实测
