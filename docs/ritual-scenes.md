# 自动化场景

> 状态：设计中 · 上位文档：[总体架构设计 §3](architecture-north-star.md#3-五类工作流)、[事件运行时与派发器](event-runtime.md)、[宿舍智能家居方案](dorm-smart.md)
>
> 自动化场景（Scene）将一组跨设备、跨工具的固定操作序列封装为单个能力，支持通过语音、NFC 标签、定时或传感器事件一键触发。场景层本身不维护独立运行时，仅按顺序向现有执行器派发步骤并向任务库写回一行执行摘要。

## 1. 场景配置规格

```toml
# scenes/morning.toml
id = "morning"
title = "晨间唤醒"

triggers = [
  { type = "clock", at = "06:40", days = "workdays" },
  { type = "me", phrase = ["早上好", "起床了"] },
  { type = "nfc", tag = "bedside" },
]
preconditions = ["home.presence == present"]

steps = [
  { id = "light",  action = "home.light.wake",   budget_s = 5 },
  { id = "render", action = "render.refresh",    budget_s = 10,  args = { surface = "desk-t5", content = "today" } },
  { id = "brief",  action = "info.feed.digest",  budget_s = 120, args = { short = true } },
  { id = "tsv",    action = "ha.service",        budget_s = 5,   args = { target = "switch.tsv_display", service = "turn_on" } },
  { id = "mode",   action = "agent.mode.set",    args = { mode = "工作" } },
]

complete = { kind = "meta.scene.morning", summary = "晨间场景完成 {done}/{total}" }
on_partial = "report"     # report | retry_once | abort
```

场景中的步骤（Step）按执行方式分为四类：

| 步骤类型 | 配置写法 | 对应执行器 | 典型操作 |
|---|---|---|---|
| 设备与命令操作 | `action = "home.*"` / `cli:*` | Home Assistant 服务、本地 CLI | 调节灯光、开关插座、刷新墨水屏 |
| Agent 生成与规划 | `action = "agent:*"` | Orca Worker | 生成当日携物建议、汇总早报摘要 |
| 人工交互确认 | `action = "me:*"` | 交互卡片 `[执行] [延后] [忽略]` | 人工确认、线下动作核对 |
| 嵌套子场景 | `action = "scene:<id>"` | 递归调用其他场景配置 | 出行前场景 = 行李清单生成 + 离宿断电场景 |

## 2. 触发方式

| 触发类型 | 配置项 | 宿舍环境适用说明 |
|---|---|---|
| 自然语言 | `type = "me"` + 触发短语 | 手机或桌面随时触发 |
| NFC 标签 | `type = "nfc"` + 标签位置 ID | 床头、门口、书桌各贴一张，手机触碰即触发，可靠性最高 |
| 定时触发 | `type = "clock"` | 适用于晨间唤醒、晚间睡前、周日复盘 |
| 家居传感器事件 | `type = "ha"` + 实体状态条件 | 门磁开启、毫米波人体存在检测、闹钟响铃 |
| 日历事件 | `type = "calendar"` + 标题关键词 | 考试周、假期出行前夕自动触发 |
| 通知模式切换 | `type = "mode"` | 退出工作模式时触发收工整理 |
| 界面按钮 | `type = "manual"` | KDE Plasma 桌面组件或 ThinkSmart View 面板按钮 |

宿舍环境下不使用手机 GPS 地理围栏或校园网 Wi-Fi SSID 作为进出判断依据（室内定位精度不足且校园网漫游频繁），统一采用**门磁传感器 + 毫米波人体存在传感器**判定在宿状态（见 [宿舍智能家居方案](dorm-smart.md)）。

## 3. 14 个预置场景清单

| 场景名称 | 触发条件 | 核心步骤序列 | 完成标志 |
|---|---|---|---|
| 晨间唤醒（`morning`） | 工作日 06:40 / "早上好" / 床头 NFC | 灯光渐亮 → 桌面 T5 刷新今日待办 → 推送早报 → 点亮 TSV 屏幕 → 切换至工作模式 | 今日待办已上屏 |
| 出门通勤（`commute`） | 工作日 07:30–09:00 门磁开启 | 门口 ESL 刷新出门携物清单 → 手机推送路况/课表 → 播报今日三项核心待办 | 出门清单已刷新 |
| 开始工作（`start-work`） | "开始工作" / 书桌 NFC | Plasma Activity 切换至"工作" → 桌面灯光调为专注色温 → 生成订阅简报 → 列出今日任务 | 工作环境已就绪 |
| 回到宿舍（`arrive`） | 门磁开启 + 30 秒内检测到人体存在（HA 本地自动化兜底） | 灯光暖白亮起 → 恢复常用插座供电 → 推送当日晚报 | 设备已恢复供电 |
| 离开宿舍（`depart`） | 连续 10 分钟无人体存在（HA 本地自动化兜底） | 关闭非必要插座电源 → 记录宿舍状态快照 → 清空门口屏幕敏感信息 | 断电并记录摘要 |
| 周末开启（`weekend`） | 周五 18:00 / "周末了" | 生成周末食谱 → 提醒洗衣与清洁排期 → 静默工作类通知 → 切换至生活模式 | 周末计划已生成 |
| 考试周（`exam-week`） | 日历含"期末/考试"或手动开启 | 暂停非必要订阅摘要 → 置顶复习计划 → 床头屏显示考试倒计时 → 切换至专注模式 | 专注复习模式已启用 |
| 出行准备（`pre-trip`） | 日历出行事件前一日 18:00 | 生成行李打包清单 → 置顶车票/酒店行程卡 → 预约离宿断电 → 提醒证件与充电宝 | 打包清单已生成 |
| 出行归来（`post-trip`） | 日历行程结束 / "回来了" | 提示导入相机照片至 Immich → 待报销账单录入 → 清空行李清单 → 恢复插座供电 | 照片与账单待办已创建 |
| 周度大扫除（`cleanup`） | 周六 10:00 / "打扫一下" | 生成分区清洁清单（书桌/床铺/地面/阳台）→ 盘点清洁耗材与垃圾袋余量 | 清洁清单已完成 |
| 周度复盘（`weekly-review`） | 周日 21:00 / "复盘" | 汇总本周完成率与返工统计 → 制定下周核心待办 → 核对月度预算 → 生成作息周报 | 周报与下周计划已生成 |
| 换季整理（`season`） | 3 / 6 / 9 / 11 月首日 | 生成衣物被褥收纳清单 → 提醒清洗空调滤网/加湿器 → 盘点换季常备品 | 换季清单已创建 |
| 晚间入睡（`sleep`） | 每日 22:30 / "睡了" / 床头 NFC | 床头屏刷新明日首项待办 → 关闭全部照明与 TSV 屏幕 → 仅保留充电插座 → 切换至勿扰模式 | 睡眠环境已就绪 |
| 观影模式（`movie`） | "看电影" | 调暗环境灯带 → 切换音频输出设备 → 手机与桌面开启免打扰 | 观影环境已切换 |

## 4. 部分完成与步骤失败处理

当场景中的某个步骤执行失败或超时，按以下规则处理，避免因单个次要步骤失败而阻塞整条场景：

| 执行情况 | 场景最终状态 | 用户收到的反馈 | 任务库记录内容 |
|---|---|---|---|
| 全部步骤成功 | `done` | `"晨间场景已完成（5/5）"` | 写入一条 `meta.scene.morning` 完成记录 |
| 非必需步骤失败 | `done`（部分完成） | `"晨间场景已完成，其中早报拉取超时"` | 标记完成，在注解中逐行记录各步骤结果 |
| 必需步骤失败 | `waiting` | `"灯光控制无响应（HA 超时）"` + `[重试] [跳过]` | 转入 `waiting` 状态，10 分钟后自动重试一次 |
| 需人工介入 | `escalated`（`+me`） | 推送交互确认卡片 | 等待人工点击确认后继续 |
| 显示端渲染超时 | `done`（部分完成） | `"桌面屏刷新超时，当前保留上一帧画面"` | 记录 `system.render.failed`，不阻塞后续步骤 |

执行约束：

1. **单条汇总记录**：每次场景执行完毕（无论全部成功还是部分完成），仅在任务库中生成一条 `meta.scene.<id>` 记录，各步骤明细写入该任务的注解中，防止一次晨间场景在任务库里刷出五条零散记录。
2. **区分必需与可选步骤**：步骤默认 `required = false`，仅对场景的核心目标步骤（如睡眠场景中的"关灯"与"切换勿扰模式"）设置 `required = true`。
3. **步骤幂等要求**：开关灯、切换插座、刷新屏幕等步骤均需保证幂等；对于非幂等操作（如热敏打印小票 `idempotent = false`），执行失败时不自动重试，直接交由人工确认。
4. **串行执行与子场景解耦**：宿舍场景步骤较少，默认按顺序串行执行；调用子场景时若子场景内某个非关键步骤失败，不阻断父场景其余步骤。

## 5. Home Assistant Automation、场景与通知模式的边界

| 机制 | 职责定位 | 执行组件 | 典型示例 |
|---|---|---|---|
| **HA Automation** | 设备级本地闭环控制与安全兜底，断网或工作站关机时仍可独立工作 | Home Assistant（运行于 N100） | 门磁开启自动亮灯、水浸传感器触发高优告警 |
| **自动化场景（Scene）** | 跨设备、跨工具的组合动作序列，可包含 Agent 任务与人工步骤 | 派发器（`evd`） | 晨间唤醒、出行准备、周度复盘 |
| **通知模式（Mode）** | 打扰与通知路由策略，仅控制通知发送时机与渠道 | Personal Agent / 派发器门控 | 工作、生活、专注、勿扰、外出、出差 |

**单向调用关系**：自动化场景可以在最后一步切换通知模式（如晨间场景切换至工作模式、睡眠场景切换至勿扰模式），也可以调用 Home Assistant 中已有的脚本或自动化；但通知模式切换不会反向触发自动化场景，避免产生循环触发。对于"回宿""离宿""入睡"等已在 Home Assistant 中配置了本地自动化的设备动作，场景配置直接通过 `ha.service` 调用它们，不在两处重复编写设备控制逻辑。
