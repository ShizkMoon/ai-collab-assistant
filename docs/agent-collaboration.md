# 多 agent 协作

## 规则入口统一

不同 agent 读取的规则文件名不同（`AGENTS.md` / `CLAUDE.md` / `GEMINI.md` / 各自配置目录下的全局文件）。用软链把它们指向同一份文件，保证所有 agent 共享同一套约定，修改只改一处。

## 上下文的分层加载

- always-on 规则：放全局与目录级 `AGENTS.md`，保持精简，细节链接到专门文档。
- 触发式规则：按主题拆分，需要时才加载，避免规则膨胀稀释注意力。
- 长期资料：沉淀到知识目录，规则文件只放指针。

## 任务边界

- 常驻服务（守护进程类工具）用系统服务管理生命周期，与交互会话解耦。
- 每个 agent 的会话、缓存、凭证保留在其原生位置；跨 agent 共享的只有规则与文档，不共享状态。
- 破坏性操作、凭据写入、对外发布统一要求显式指令。
