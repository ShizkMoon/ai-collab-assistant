# 多 Agent 协作规范

## 1. 统一规则入口

不同 Agent 工具默认读取的规则文件名各不相同（如 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md` 以及各自配置目录下的全局文件）。本机通过符号链接（`~/.agents/link-skills.sh`）将它们统一指向同一份源文件，确保所有 Agent 共享一致的工程规范，修改时只需维护一处。

## 2. 上下文分层加载

- **常驻基础规则（Always-on）**：存放在全局与项目根目录的 `AGENTS.md` 中，保持简明扼要，具体领域细节通过相对路径链接指向专题文件。
- **按需加载技能（Skills）**：按具体任务类型拆分为独立 Skill，命中任务类型时才加载对应说明，避免常驻上下文膨胀分散模型注意力。
- **历史经验与笔记**：沉淀在 `~/.agents/notes/` 与本地知识库（`~/knowledge/kb.sqlite`）中，通过 `kn recall` 按需检索。

## 3. 运行状态与权限边界

- 常驻后台服务由 `systemd` 统一管理生命周期，与单次交互式 Agent 会话解耦。
- 每个 Agent 的会话记录、缓存与登录凭据保留在各自原生目录中；跨 Agent 仅通过磁盘文件与任务库交接，不直接共享内存状态。
- 全系统仅对**付款、删除、对外发布**三类操作要求人工确认（[ADR 0002](adr/0002-three-confirmation-points.md)）；其余操作直接执行，依靠执行摘要与撤销窗口兜底。

## 4. 多 Agent 协作模式

跨 Agent 协同遵循两条基本原则：通过 Taskwarrior 的 `thread` 与 `parent` 字段交接任务进度，不进行跨 Agent 自由对话；阶段产物全部落盘为文件，上下游之间只传递文件路径。

| 协作模式 | 适用场景 | 运作方式 |
|---|---|---|
| **阶段流水线（Pipeline）** | 视频制作、播客剪辑、电子书精修 | 素材导入 → 初稿 → 审校 → 合成 → 导出，每阶段可独立替换 Provider |
| **并行分节（Map-Reduce）** | 长文写作、多方向文献调研 | 协调 Worker 拆解提纲 → 多个 Worker 并行撰写各章节 → 汇总统稿 |
| **异构模型交叉评审（Author + Reviewer）** | 代码开发、长文审校 | 使用不同厂商的模型分别承担编写与审阅（如 DeepSeek 编写、Qwen 或 Claude 审阅），减少同源盲区 |
| **协调者模式（Coordinator + Workers）** | 跨领域复杂项目 | 单个协调 Worker 维护 `thread` 整体进度与依赖检查，其余专项 Worker 仅处理具体子任务 |
| **多候选比选（Best-of-N）** | 封面制作、标题起草、配乐生成 | `meta.contest.run` 并行调用多个 Provider 各出一版，人工挑选结果写入 `choice.json` 并作为偏好样本 |

由于所有模型统一经 LiteLLM 网关调用，切换不同厂商的审稿模型只需在派发参数中更改模型名称。

- **内容创作与多候选比选**的七段式管线细节见 [内容创作流水线](creative-studio.md)。
- **代码开发任务**的九个标准阶段与 Git Worktree 隔离规范见 [开发与逆向工程 §1](work-devsec.md#1-代码开发流水线)。

### 4.1 长文写作协同示例

```text
用户需求：撰写一篇 NixOS + KDE Plasma 6 桌面迁移总结
协调 Worker → 生成章节提纲（推送卡片供用户确认）
            → 派发 3 个写作 Worker 并行撰写各节（各自调用 info.recall 检索历史配置记录）
            → 派发异构模型审校全文 → 统稿并转换为微信公众号排版 HTML
            → 推送卡片："初稿已完成（3200 字），[查看] [修改] [提交发布]"  ← 对外发布触发确认点
```

### 4.2 视频制作协同示例

```text
用户需求：将周末爬山拍摄的素材剪辑为 3 分钟 Vlog
协调 Worker → 调用 work.video.ingest 归一化素材并切分镜头 → 粗剪（Remotion / auto-editor）
            → 派生子任务 work.music.compose 生成配乐（ACE-Step）
            → 语音转写生成字幕（SenseVoice）→ 触发 meta.contest.run 生成 3 张候选封面
            → 推送卡片："成片 3:12 已导出，[预览] [更换配乐] [选择封面] [生成投稿草稿]"
```
