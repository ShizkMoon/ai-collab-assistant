# ADR 0004：草稿层设置 24 小时 TTL，正式任务与提案不设过期清理

系统在正式任务库前增设一层"草稿（Draft）"：对话中产生的临时想法或预生成方案在人工确认前先存为草稿，超过 24 小时未转为正式任务则自动清理。而正式任务记录、知识库文档、偏好配置与演进提案均不设置自动过期。

**决策依据**：若缺乏草稿层，未定型的临时想法要么直接写入 Taskwarrior 导致任务库堆积大量无效待办，要么湮没在聊天历史中无法追踪。为草稿设置 24 小时 TTL 可以降低随手记录的心理负担；而一旦确认为正式任务或演进提案，其执行与成败记录就是后续周报复盘与规则挖掘的基础样本，必须长期保留。

**架构影响**：需要配置每日定时清理过期草稿的任务（或通过 Taskwarrior 的 `wait:<ttl>` + `+spec` 状态自动回收）；若同一草稿主题被反复重新创建，周度复盘会将其识别为高频需求并提示转为正式任务或能力提案。
