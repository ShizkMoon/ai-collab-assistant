# ADR 0005：通过"提案 → 影子测试 → 上线"迭代系统，禁止自动改写配置

周期复盘或模式挖掘产出的改进方案，不得直接覆写线上规则表、能力目录或提示词，必须先生成书面提案、在影子测试模式下旁路运行验证，最后通过显式的提交操作正式启用。禁止 Agent 在运行过程中直接改写自身的线上规则与提示词配置。

**决策依据**：允许 Agent 自动改写线上配置的最大风险在于**行为漂移难以归因**。当系统某天出现异常路由或错误输出时，排查者很难定位是哪一次自动改写引入的问题。通过 `docs/proposals/` 为每次变更建立独立提案文件并记录支撑证据，可确保任何行为变化都能通过 Git 历史追溯到具体原因；影子测试则将新能力验证期的试错成本隔离在旁路目录内。

**替代方案取舍**：未采用 DSPy / TextGrad 式的在线持续重写，也未采用每周自动合并 Top-K 候选规则的做法。前者依赖具有一定规模的标准评测集，后者在个人日常低频样本下极易将偶然噪声固化为错误规则。
