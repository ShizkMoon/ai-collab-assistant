# ADR 0007：常驻入口延后，先单机加云端等待队列

N100 迷你主机因成本原因暂不采购（2026-11-02）。[ADR 0003](0003-loop-local-entry-remote.md) 的「入口常驻 N100」在硬件到位前无法落地：常驻入口暂时由已有的云服务器 `orca-pool` 承担，只负责接收消息、写入等待队列；工作站承担全部编排与执行。

**决策依据**：常驻入口要解决的硬需求是「消息不丢」，不是「消息被立刻处理」。`orca-pool` 已 24 小时在线并接入 Tailscale，能跑 ntfy 与极小的消息网关；工作站休眠时消息进云端等待队列，醒来后由派发器消费。为这一点再添一台常开主机，收益不抵成本。

**代价**：

1. **单点。** 工作站关机期间系统整体不可用，只剩云端等待队列；ADR 0003 设想的「轻量任务在常驻节点本地执行」不存在。
2. **家居能力顺延。** Home Assistant、Zigbee2MQTT、n8n 都依赖常开主机，随 N100 一起推迟。
3. **唤醒与 UPS 联动失效。** 没有第二台机器发 WoL，也没有第二台机器做 NUT primary，相关方案降级为「工作站保持唤醒」。

**复评条件**：出现以下任一情况时重新评估常驻节点——家居设备需要 24 小时本地自动化；工作站关机期间的消息丢失造成实际损失；二手瘦客户机（约 ¥200–400）可用。届时常驻节点优先选二手瘦客户机而非 N100。
