# DNS 真实短窗结果与 HTTPS 下一步

读取范围：仅 `work/deploy/dns-ab-campus.json` 与 `work/deploy/dns-ab-public.json`，未读私密配置，未连设备。数据时间为 2026-10-12 07:43～07:46 UTC。安装与执行由主代理完成。

校园 DNS 10.50.11.15 在四个公共域名、两轮共 8 次 A 查询全部超时，约每次 2 秒；不能由此断定校园认证域名同样不可解析，也不能推断学校 DNS 永久失效。当前电信 DNS、dnsmasq 和 SmartDNS 均返回正确形态的公共答案，后两者未改变此查询集合。

公共上游池且无主动选址时，电信与 SmartDNS 回答的 IP 集合一致，只是顺序改变。两轮共 8 次的粗粒度耗时：电信平均约 1.25 ms、SmartDNS 平均约 1.25 ms；这些平均值来自 0/10 ms 的计时值，不能作毫秒精度性能声明。主动选址后 SmartDNS 为 10～20 ms，约平均 15 ms；同轮电信 0～10 ms、约平均 7.5 ms。当前没有 DNS 响应时间收益。

SmartDNS 主动选择的 IP 固定为 qq `121.14.77.221`、bilibili `14.17.92.74`、taobao `14.29.48.55`；京东保持原来的唯一 IP `119.147.159.135`。公共 DNS池未提供新的地址集合，现阶段主要变化是挑出一个地址以及响应等待；是否改善 HTTPS 需应用层小样本证实。

`https-ab.sh head` 为每域两个 IP、两轮反序，12 次 HEAD，每次 5 秒上限，不 follow redirect，不使用 `-k`，固定 hostname/SNI/URL。`https-ab.sh range` 是显式备选，另外12次最多1KiB Range请求，响应大小允许上限64KiB；服务器不支持HEAD或HEAD返回特殊处理时才使用，不应两种模式都无条件扩大测量。

记录 connect、TLS累计时间、首字节累计时间、实际远端IP、HTTP状态、TLS验证结果、curl返回码。首字节是请求开始以来累计时间；TLS=0及verify=0不能单独证明握手成功，必须结合rc、非0HTTP与time_appconnect。HTTP 301/302/403/412 不直接等同网络故障；同域不同IP返回不同防爬页面时不能把响应更快等同正常页面更快。

本脚本禁用curl显式代理环境，但不能绕过路由器已启用的透明代理；主代理必须确定测试域名走DIRECT并记录出口，否则不能把路径变化解释为CDN地址效果。当前地址属于读取时DNS集合，运行前如已漂移，应重新核对，不把它们写成永久hosts。

在当前短样本没有明显且稳定的HTTPS收益时，建议不把SmartDNS放入全LAN/所有国内域名生产路径，保留独立部署与回滚能力即可。若一个具体域名两轮都有明显改善且语义/TLS完整，可只对该域名采用限定分支；还需把额外DNS等待算入总访问时间。两轮仅可排除明显差异，不能证明稳定全时收益。
